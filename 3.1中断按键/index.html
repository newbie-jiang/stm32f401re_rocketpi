    3.1中断按键

    功能：使用中断按键翻转LED¶

    1.进入mcu选择器界面¶

    • 打开STM32cubeMX，点击ACCESS TO MCU SELECTOR

    2.选择芯片型号¶

    • 步骤1：在Commercial Part Number 输入 F401RE
    • 步骤2：选择STM32F401RET6 （其他芯片可自行选择）
    • 步骤3：点击Start Project

    3.晶体振荡器选择¶

    • 步骤1：点击System Core
    • 步骤2：点击RCC
    • 步骤3：High Speed Clock(HSE) 选择 Crystal/Ceramic Resonator

    4.时钟配置¶

    • 步骤1：点击Clock Configuration
    • 步骤2：input frequency输入8 (因为 rocketpi 硬件设计使用外部晶振为8Mhz，所以此处输入8)
    • 步骤3：选择HSE
    • 步骤4：在HCLK的输入框中输入84，接着回车，回车之后可能会弹出一个确认框，点击OK,会自动配置时钟，等待配置完毕

    5.配置调试接口¶

    • 步骤1：点击SYS
    • 步骤2：Debug选择栏 选择Serial Wire

    6.配置LED的io为输出¶

    在配置之前看原理图，我们需要看led的原理图，找到LED的原理图部分，从原理可以获得的信息

    • 三个LED连接的引脚分别为 PA1,PB10,PB14
    • 三个LED都是低电平点亮

    图形化配置

    • 步骤1：搜索框中输入PA1，回车，这时候PA1的引脚会闪烁
    • 步骤2：点击闪烁的PA1
    • 步骤3：将PA1设置为GPIO_Output

    接下来另外两个led的io PB10,PB14 操作也和上述一样

    • 配置完成后确保这三处地地方一致

    点击GPIO,可以看到我们的配置的三个LED出现在这里了

    7.配置LED的电气属性¶

    由于三个LED都是低电平点亮，一般 初始化的过程，我们会配置关闭LED，

    • 分别点击 PA1,PB10,PB14，将GPIO output level 属性设置为high,配置后烧录程序默认会关闭LED
    • 默认的GPIO mode 是推挽输出（推挽输出可以输出高电平，也可以输出低电平），此处我们不需要更改gpio的模式了,至此lLED的配置已经完成了

    8.配置按键¶

    在配置之前看原理图，找到按键的原理图部分，从原理可以获得的信息

    • 使用PA0做按键引脚
    • 按键按下时，PA0会检测到低电平
    • 配置为下降沿触发

    • 步骤1：输入框中输入PA0 回车,
    • 步骤2：点击闪烁的PA0
    • 步骤3：将PA0配置为GPIO_EXTI0 (GPIO的外部中断)

    9.配置下降沿中断¶

    • 步骤1：点击GPIO
    • 步骤2：点击PA0的打开配置项
    • 步骤3：配置GPIO mode为下降沿触发
    • 步骤4：在User lable给PA0 起一个别名 KEY_PA0

    10.开启中断¶

    • 步骤1：点击NVIC （Nested vectoredinterrupt controller），嵌套向量中断控制器，可以理解为管理所有中断的
    • 步骤2：EXTI line0 interrupt 打钩，表示开启外部中断线0（由于设置了PA0，PA0对应中断线0）

    11.生成代码¶

    • 步骤1：点击Project Manager
    • 步骤2：填写此次要创建的工程名字，（注意这里一定不要使用中文名）
    • 步骤3：这个工程保存的路径（注意这里一定不要有中文路径，否则生成的工程会有问题）
    • 步骤4：生成的工程选择 MDK-ARM 版本为v5.27（版本可以根据自己安装keil版本选择，一般来说高版本的keil可以向下兼容）

    • 点击Code Generator
    • 软件包选择 copy only the necessary files (仅复制使用到的库文件)
    • 生成的文件选择 Generate peripheral initialization as a pair .c/.h files perpheral

    最后，点击GENERATE CODE 即可生成代码

    12.打开keil工程¶

    • 点击OPen Project即可打开刚创建好的工程（电脑已经安装了keil的前提下）

    13.编译¶

    确保编译日志 0错误，0警告（这一步出问题了就是工程名字或者工程路径存在中文）

    void HAL_GPIO_EXTI_IRQHandler(uint16_t GPIO_Pin)
{
  /* EXTI line interrupt detected */
  if(__HAL_GPIO_EXTI_GET_IT(GPIO_Pin) != RESET)        // 1) 查：该引脚对应的 EXTI 挂起标志是否置位
  {
    __HAL_GPIO_EXTI_CLEAR_IT(GPIO_Pin);                // 2) 清：清除该 EXTI 挂起标志（写1清除）
    HAL_GPIO_EXTI_Callback(GPIO_Pin);                  // 3) 调：调用用户可重写的回调函数
  }
}
    • 最终会调用到HAL_GPIO_EXTI_Callback(GPIO_Pin); 函数，我们一般把这样的函数叫做中断回调函数，查看该函数实现

    __weak void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
  UNUSED(GPIO_Pin);   // 防止未使用形参导致编译告警
  /* NOTE: 不要改这里（HAL 源码）。
           需要回调时，请在用户文件里实现同名函数覆盖它。 */
}

    要点：

    1. __weak
    2. “弱符号”。如果你的工程中定义了同名的非弱函数，链接时会用你的实现覆盖这里的空实现。
    3. 这样 HAL 保留统一接口，你按需提供业务逻辑。
    4. UNUSED(GPIO_Pin)
    5. 只是消除“形参未使用”的告警；默认空实现里没有用到它。
    6. 不要修改 HAL 源码
    7. 以后升级 HAL 容易被覆盖。正确做法是在用户代码（如 stm32xxxx_it.c、main.c 或你自己的 .c）里写一个同名函数。

    将函数去掉__weak ，放在文件stm32f4xx_it.c

    • 此处就是按键按下，留给我们需要编程的地方

    重点：中断要求快进快出，我们不会在中断里面加延时函数，一般会触发一个标志位，在main函数里面做处理

    /* 在中断与主循环之间传递事件的标志位
 * volatile 防止编译器优化缓存，保证主循环能读到中断里最新写入的值
 */
volatile uint8_t key_flag = 0;

/**
 * @brief  外部中断回调（HAL 会在 HAL_GPIO_EXTI_IRQHandler() 中调用这里）
 * @param  GPIO_Pin 本次触发的 EXTI 引脚对应的“线”，例如 GPIO_PIN_0
 */
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
  /* 只处理我们关心的按键那一条 EXTI 线（例如 PA0） */
  if (GPIO_Pin == KEY_PA0_Pin)
  {
    /* 记录“上一次被判定为有效按键事件”的时间戳（ms）
     * static 保留上次值；放在这里即可，不必全局
     */
    static uint32_t last_press_tick = 0;

    /* 当前毫秒节拍（由 SysTick 提供，默认 1ms 递增） */
    uint32_t now = HAL_GetTick();

    /* 20ms 软件去抖：
     * 使用无符号减法比较 (now - last_press_tick) >= 20
     * 即使 HAL_GetTick() 发生 32 位溢出也能正确比较
     */
    if ((now - last_press_tick) >= 20U)
    {
      /* 更新最近一次“有效事件”时间点 */
      last_press_tick = now;

      /* 置位事件标志，让主循环读取后处理（并清零） */
      key_flag = 1;
    }
  }
}

    声明一个在别处定义的全局变量（通常在中断回调里置位）。

    volatile 确保主循环每次都从内存读取最新值（因为中断可能随时修改它）。

    轮询事件：如果 key_flag 被中断置位（=1），就进入处理分支。

    清零标志：key_flag = 0; 表示“这次事件已处理”，防止重复触发。
